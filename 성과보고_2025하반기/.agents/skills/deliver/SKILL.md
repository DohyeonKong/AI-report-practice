# deliver — 전달

## 입력
- `reports/초안/draft_v2.md`, `reports/초안/review_log.md`, `reports/초안/charts/`
- `resources/취합/requirements.md`, `fact_sheet.csv`, `conflicts.md`
- `templates/요약보고_양식.md`, `templates/메일양식.md`

## 출력 (`reports/전달/`)
| 파일 | 독자 | 분량 |
|---|---|---|
| `총장보고_1쪽요약.md` | 총장 | A4 1쪽 |
| `보고메일.md` | 위원회·결재선 | 10줄 이내 |
| `학과공유문.md` | 학과장·교직원 | 1쪽 이내 |
| `부서별_확인요청.md` | 자료를 낸 부서 | 부서당 5줄 이내 |
| `예상질의응답.md` | 보고자 본인 | 5~7문항 |
| `결재용_최종본.md`, `결재용_최종본.docx` | 결재·제출 | 양식 분량 이내 |

## 절차

### 1단계. 독자별 문서 만들기
1. `requirements.md`에서 독자별 산출물, 기한, 공유 제한을 다시 확인한다.
2. 양식의 칸을 채운다. 숫자는 `draft_v2.md`와 같아야 하고, 독자에 따라 바꾸는 것은 분량과 어조뿐이다.
   - 총장 요약: 결론 3줄, 미달 항목과 대책, '결정 요청'(미결정 안건).
   - 학과 공유문: 개인정보와 단위과제별 집행 세부는 빼되, 불리한 전체 결과(미달 지표, 전체 집행률)는 남긴다.
   - 부서별 확인 요청: `draft_v2.md`의 `[담당부서 확인 필요]` 항목과 `conflicts.md`의 자료 오류(예: 단위 입력 오류)를 부서별로 묶어, 무엇을 언제까지 보내 달라는지 쓴다. 회신 기한은 `[회신 기한]`으로 비워 두고 사용자가 정한다.
   - 예상 질의응답: '자료마다 숫자가 달랐던 이유'를 반드시 1문항 넣는다.
3. 다섯 문서의 숫자가 서로 같은지 확인한다.

### 2단계. 멈추고 확인 받기
만든 문서 목록과 '사용자가 채워야 할 칸'(회신 기한 등)을 보고하고 멈춘다.

### 3단계. 결재용 최종본
1. `draft_v2.md`에서 팩트 주석(`<!-- fact: … -->`)과 작업 메모를 지워 `결재용_최종본.md`로 저장한다.
   그림 경로는 `reports/전달/` 기준으로 고친다(예: `charts/…` → `../초안/charts/…`).
2. docx로 변환한다.
   `python .agents/skills/deliver/scripts/md_to_docx.py "reports/전달/결재용_최종본.md" "reports/전달/결재용_최종본.docx"`
   (python-docx가 없으면 사용자에게 묻고 `pip install python-docx`)
3. 최종 점검: 분량, 표 깨짐, 차트 포함, 주석 잔존 0건, `[담당부서 확인 필요]`가 남아 있으면 목록으로 보고.
4. 한글(HWP) 제출이면, docx를 한글에서 열어 기관 양식에 붙여 넣도록 안내한다.

## 검증 기준
- 산출물 간 숫자 일치
- 학과 공유문에 공유 제한 정보 없음, 불리한 전체 결과 누락 없음
- 최종본에 주석·작업 메모 0건

## 웹(Gemini·ChatGPT)에서 쓸 때
- 1단계만 한다. docx는 Gemini Canvas → 'Google Docs로 내보내기'로 만든다.
