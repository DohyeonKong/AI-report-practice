# write-report — 작성

## 입력
- `resources/취합/requirements.md`, `fact_sheet.csv`, `conflicts.md`
- `templates/성과보고서_양식.md`
- 근거 확인용: `resources/기준/` 회의록

## 출력 (`reports/초안/`)
| 파일 | 내용 |
|---|---|
| `outline.md` | 섹션별 한 줄 결론, 사용할 팩트, 분량, 요구사항 충족표 |
| `analysis.md`, `charts/*.png` | 지표 판정표, 예산 집행표, 참여 실적표, 미달 원인 후보 |
| `draft_v1.md` | 개조식 초안(숫자마다 팩트 주석) |
| `review_log.md` | 검토 결과와 조치 |
| `draft_v2.md` | 검토 반영 수정본 |

## 절차

### 1단계. 목차 → `outline.md`
1. `templates/성과보고서_양식.md`의 목차 순서를 그대로 따른다.
2. 섹션마다 한 줄 결론(두괄식)과 사용할 팩트 항목을 적는다.
3. `requirements.md` 체크리스트의 각 항목이 어느 섹션에서 충족되는지 표로 만든다.
4. 분량 제한에 맞춰 섹션별 분량을 배분한다.

### 2단계. 분석 → `analysis.md`, `charts/`
1. 계산은 코드로 하고 코드를 남긴다(`reports/초안/analysis.py`). 팩트시트의 '확정' 값만 쓴다.
2. 지표 판정: 높을수록 우수는 실적 ≥ 목표, 낮을수록 우수는 실적 ≤ 목표일 때 달성. 차이는 %p 또는 점.
3. 예산: 단위과제별 집행률 = 집행액 / 예산 × 100, 전체 집행률은 개별 합으로 다시 계산. 목표 미만 과제를 낮은 순으로 정렬.
4. 참여 실적: 목표 대비 달성률.
5. 미달 항목마다 원인 후보를 회의록에서 찾는다. 없으면 '원인 확인 필요'.
6. 차트는 2개 이내. 막대는 0에서 시작하고 목표선을 표시한다.

### 3단계. 초안 → `draft_v1.md`
1. 양식의 각 칸을 채운다. 양식의 안내 문구(대괄호)는 지운다.
2. 각 □ 바로 아래 첫 ○는 그 항목의 결론.
3. 숫자마다 팩트 주석을 단다: `<!-- fact: 집행률_합계 -->`
4. 미달 지표는 '현황 → 사유 → 개선계획'. 근거 없는 칸은 `[담당부서 확인 필요]`.
5. 우수사례는 '내용 → 성과(숫자) → 근거(설문·의견)' 3~4줄. 학생 의견은 마스킹 사본에서만 인용한다.

### 4단계. 검증 → `review_log.md`, `draft_v2.md`
1. 숫자 대조: 초안의 숫자를 모두 뽑아 팩트시트와 한 줄씩 대조한다.
2. 판정 대조: 달성/미달이 지표 방향과 맞는가.
3. 요구사항 대조: 체크리스트를 하나씩 확인한다.
4. 근거 대조: 사유·계획 문장마다 근거가 있는가, 미결정 사항을 확정처럼 쓰지 않았는가.
5. 개인정보·공유 제한 정보가 없는가.
6. 교차 리뷰: 사용자가 다른 AI(초안을 쓰지 않은 모델)에 아래 프롬프트로 리뷰를 맡기도록 안내하고, 받은 지적을 반영한다.
   > 너는 이 보고서를 처음 보는 깐깐한 사업 평가위원이다. 숫자의 앞뒤가 맞지 않는 곳, 근거 없는 주장, 빠진 설명을 5개 이내로 지적하라. 칭찬은 하지 마라.
7. `review_log.md` 형식: 점검 항목 | 결과(통과/수정/보류) | 근거 | 조치. 반영하지 않은 지적은 이유를 적는다.
8. `draft_v2.md`는 팩트 주석을 남긴 채 저장한다(최종 제거는 deliver에서).

### 5단계. 멈추고 확인 받기
달성/미달 요약, 보류 항목(확인 필요) 수, 분량을 보고하고 멈춘다.

## 검증 기준
- 숫자 대조 불일치 0건
- 요구사항 체크리스트 미충족 0건(또는 보류 사유 명시)
- 자료에 없는 사유·계획 0건

## 웹(Gemini·ChatGPT)에서 쓸 때
- Gemini는 Canvas에 초안을 쓰고, ChatGPT는 데이터 분석으로 계산한 뒤 코드를 보여 준다.
- 출력 파일은 파일명을 제목으로 단 코드 블록으로 보여 준다.
